Cast: live media in
Pyrenet

Cast is the live-media layer inside Pyrenet. Pick a whole screen or a single window on Windows, then send it to a second Windows PC or an Android phone. The picture travels over Pyrenet's encrypted fabric.

Audio and remote-input
permissions

Choose whether to share computer audio, enable your microphone, or allow mouse and keyboard control. Computer audio has historical LAN evidence; this build still needs physical-device checks for audio and remote input.

Computer audio Available

The sending PC’s own sound travels with the picture. A Windows viewer decoded it in the LAN run; audible output on a phone was not independently confirmed.

Microphone voice Preview

Microphone voice is optional and supports two-way communication. Automated checks pass, but physical round-trip and echo testing remain outstanding.

Remote input Preview

Allow the watching device to control the mouse and keyboard. Physical input and behaviour inside native games remain unverified.

Hardware and Windows permissions still apply on top of these switches. See the capability table below for the published release’s status.

Sending and watching

Included screen-sharing features, with device requirements and testing results.

CapabilityStatusWhat to expect
Screen and window captureAvailableShare an entire screen, or pick a single window, from a Windows x64 PC.
Video quality controlsAvailableBefore sharing, choose 60 or 30 fps, 50–100% resolution, and 5–50 Mb/s picture detail. Reduced resolution uses CPU encoding in this preview; sustained 60 fps is not promised on every PC.
H.264 encodingPreviewWindows shares H.264 using the available encoder. Hardware support and CPU cost vary; this build has not been validated on every vendor.
Android receivingPreviewAndroid 8 or newer receives screens using its decoder. This release includes ARM64 and x86-64 native libraries; physical playback remains unverified for these packages.
Windows receivingAvailableA second Windows PC can receive the screen and system audio. Both ends need matching builds.
Computer audioPreviewThe sending PC can include system audio with its screen. Audible output and endurance remain unverified for this build.

Features awaiting physical validation

These features are included, but physical-device tests remain outstanding.

CapabilityStatusWhat to expect
Private session admissionPreviewThe viewing device issues a private invitation that authorises the session over a pinned QUIC connection. Expiry, replay, and revocation pass loopback tests; physical regression testing is still open.
Two-way microphone voicePreviewOne-to-one and group calls use direct peer paths with relay fallback. Physical microphone, echo and network-handoff checks remain outstanding.
Remote control from AndroidPreviewAndroid receives screens. It does not currently provide the account proof required by named-account remote-control grants, so those sessions remain view-only.
Cursor appearance and effectsPreviewDesktop cursor styling with a local effects budget. The current build labels this preview only.
Several viewers on one sharePreviewOne Windows capture can serve up to eight independently admitted viewers. Windows Tables subscribe to up to four live friend screens and support late joins. Physical multi-device acceptance remains open.
Sharing a screen during a callPreviewA call and a screen share can run together. Accepted Windows friends discover live Table shares automatically after the sender explicitly starts sharing.
Windows Table layout and fullscreenPreviewSeats resize from every edge and corner. Settings are menus; fullscreen hides the surrounding UI. Interactive acceptance remains open.
Profile picturesPreviewWindows and Android support choosing, changing and removing profile pictures. Android uses explicit Save and Discard controls.
In-call text and filesPreviewWindows and Android include session chat and consent-based file transfer. Files require a direct route; session chat is not a durable offline archive.
Automatic update checksPreviewThese matched downloads include the update manifest used by the Windows and Android preview update channel. Installer/update lifecycle validation remains open.

Features with additional limitations

Internet playback remains unqualified, and accounts and contacts have local-storage limitations.

CapabilityStatusWhat to expect
Viewing outside your local networkPreviewDirect routes are preferred and the Pyrenet relay provides fallback. This build includes negotiation and route-repair fixes, but unrelated-network physical acceptance remains open.
Device-owned accounts and contactsPreviewDevice-held keys identify accounts. The coordination service supports profiles, friends and invitations; it is not a fully decentralized account service.

Preview 9 build and package checks

Matching 0.3.3 Preview 1 Windows and Android packages

  • Windows desktop and capture host built in release mode.
  • Android ARM64 and x86-64 native libraries rebuilt; APK assembly and lint completed.
  • Package versions, Android signature, APK structure and updater manifest checked.
  • Installer, APK and portable bundle have published SHA-256 checksums.

These are compilation and package-integrity checks. They do not establish visible playback, audible calls or daily-driver reliability.

  • Interactive resize/reconnect, selected-resolution display, audio and screen-sharing acceptance remains open.
  • Separate-network direct/relay sessions and extended physical-device use remain unverified for these packages.
  • A two-client automated public-relay run exceeded 30 seconds; it is not physical-device acceptance.

Original release notes ↗

Direct connections are preferred, with a Pyrenet relay fallback. Multi-viewer sharing is experimental and has loopback test coverage; physical multi-device sharing remains unqualified. Unrelated-network playback remains unqualified. Explore the connection design. Release notes cover what each tag ships, and the issue tracker is where gaps get reported.

Pyrenet

Screen sharing with a little magic and careful networking.

Screen sharing does not require an account. Friends, calls, rooms and files use a device-owned account in this development preview. Cast supplies the live-media layer inside the broader Pyrenet ecosystem.

Native application source is maintained separately. This repository publishes the website and preview packages only.
