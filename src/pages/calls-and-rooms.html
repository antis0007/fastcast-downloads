Calls, rooms & files

Talking while
you share

A {{PRODUCT}} session is not only a picture. Two people, or a small group, can talk over the same connection, keep a written room alongside it, and hand each other a file. Every part of this is preview work, and this page states what each one still cannot do.

Voice

Microphone audio on the same route

Calls take the same path as screen video: a direct peer route where one exists, a {{PRODUCT}} relay only when it does not.

One-to-one and small groups. Both use direct peer paths with relay fallback. No call is placed through a hosted meeting service.

A call and a share run together. You can start a screen share during a call, and accepted Windows friends discover the live share once you explicitly start it. Nothing is shared before that moment.

Not proven on real hardware. Physical microphone behaviour, echo, and a device moving between networks mid-call are outstanding checks. Treat voice as preview, not as a phone replacement.

Which devices can do what →

Tables

Watching more than one screen

A Windows Table holds several live screens at once, each admitted individually.

One share, many viewers

Up to eight

A single Windows capture serves up to eight separately admitted viewers. Each is admitted by invitation; there is no open link anyone can follow.

One Table, many shares

Up to four screens

A Windows Table subscribes to as many as four live friend screens, and someone joining late still receives the picture.

Layout

Yours to arrange

Seats resize from any edge or corner, settings stay in menus, and fullscreen hides everything around the screens.

Multi-device acceptance remains open. This has been exercised in development, not across a room of unrelated physical machines.

Rooms

Written conversation beside the session

Room discussions run through the coordination service, so a room outlives any single call.

Three columns. Rooms on the left, the conversation in the middle, who is present on the right. Both side rails fold away on a narrow window so the conversation keeps the space.

Built to be read. Messages from one person within five minutes group under a single header. A line marks where you left off and holds its position while you read it, and “Jump to latest” appears once you scroll back.

Quote and copy. Hovering a message offers both, so a reply can point at what it answers.

The three-column discussion layout is in development and is not part of the published download. See the release notes.

Files

Handing over a file

Windows and Android can send each other a file during a session. The receiving side accepts it explicitly, so nothing arrives unannounced, and the transfer requires a direct route between the two devices.

There is no relay fallback for files. Where only a relayed route exists, the transfer does not start rather than quietly consuming relay bandwidth.

Session chat and transfers are not an archive. {{PRODUCT}} is not holding your conversation on a server for you to return to.

What is missing

Stated here so you meet it now rather than mid-session.

No reactions, editing or deleting messages. The coordination service has no operation for them, so the app does not present controls that would do nothing.

No unread counts on rooms you are not currently reading, for the same reason.

No durable offline chat. Messages belong to the coordination service, not to a mailbox that holds them for a device that is switched off.

Android does not broadcast a screen and cannot drive remote control, because it does not yet provide the account proof that named remote input requires.

Where this is going →

Accounts are held by the device

A device-held key identifies an account. The coordination service carries profiles, friends and invitations, including profile pictures you can choose, change or remove on either platform. It is a small coordination service rather than a fully decentralised identity system, and this site does not claim otherwise.
