Connections

Direct connections
and relay fallback

FastCast sends your screen straight to the viewing device whenever it can. If that route fails, the encrypted media goes through a relay instead.

{{SCRYING_ORB}}

Your Windows PC encodes the picture and the viewing device decodes it. When the relay is used, it forwards encrypted packets; it never plays or re-encodes them.

Pairing and discovery messages help the two devices find each other. They travel separately from the screen and audio.

Start on your own network.

Earlier builds were tested on a local network. This build still needs physical playback verification on local and separate networks. Networks that block UDP have no media fallback.

Help

Common setup
questions

Most first-session failures come down to mismatched versions, guest Wi-Fi isolating the devices, or a stale invitation. Check those three before filing a bug.

The devices won't connect.

Use matching versions on both devices and check that they can reach each other. Guest Wi-Fi can isolate devices even when they share a network name. Make a fresh invitation on the viewer and import it on the sharing PC. Connection checklist.

Is this remote control, or watching?

Screen sharing works with remote input disabled. Remote input is an experimental option for mouse and keyboard control; responsiveness in games has not been established.

What do I need before installing?

Windows x64 to send, and a second Windows PC or Android 8+ to watch. The Windows installer is unsigned and the APK is debug-signed, so check the published checksum. Install notes.
