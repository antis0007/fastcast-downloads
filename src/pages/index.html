Connections

Direct connections
and relay fallback

FastCast first tries to send the screen directly to the viewing device. If that connection fails, it can send the encrypted media through a relay.

{{SCRYING_ORB}}

The Windows PC encodes the screen; the viewing device decodes it. The relay forwards packets without playing or re-encoding the picture.

Pairing and discovery help the devices find each other. Those setup messages are separate from the screen and audio.

Start on your own network.

The recorded media test used LAN. Internet playback remains unqualified; networks that block UDP have no media fallback.

Why FastCast

A separate app
for screen sharing

Use FastCast for the screen share while keeping your conversations in the chat app you already use. You do not need to move your contacts or community to try it.

This preview focuses on sharing a Windows screen with another PC or Android device. It does not provide a complete replacement for messaging, meetings, or hosted communities.

Help

Common setup
questions

Check device requirements, invitations, and permissions when setting up your first session.

The devices won't connect.

Use matching versions on both devices and check that they can reach each other. Guest Wi-Fi can isolate devices even when they share a network name. Make a fresh invitation on the viewer and import it on the sharing PC. Connection checklist.

Is this remote control, or watching?

Screen sharing works with remote input disabled. Remote input is an experimental option for mouse and keyboard control; responsiveness in games has not been established.

What do I need before installing?

Windows x64 to send, and a second Windows PC or Android 8+ to watch. The Windows installer is unsigned and the APK is debug-signed, so check the published checksum. Install notes.
